# 验收与交付

按修改范围执行。首次生成完整作品时检查下列内容；后续只修改文字时无需机械重复整套美术流程。

## 静态检查

初版运行 `scripts/check_project.py <用户项目目录> --stage draft`；正式交付运行 `scripts/check_project.py <用户项目目录> --stage final`。脚本检查 HTML 基础结构、重复 ID、导航锚点、显式资源引用和本地 CSS 资源，以及潜在远程运行依赖；还统计占位图并核对 JSON 格式 MAP_PLACES 中必需的地点插画。final 模式发现必需插画缺失或多张占位图会失败。主要地点默认需插画，明确只需标记的点由确认方案设 art_required:false。仅用户明确选择矢量风格时可加 --accept-vector 并记录选择。它不会证明动态地图、美术效果或用户行程准确。

另外核对动态生成的 `MAP_PLACES[].art`、照片 `FALLBACK`、路线索引、segments ID 及脚本语法。若发现源文件中存在本机绝对路径、data/blob 临时图片、模板示例标题或旧行程，先修复。

按已选地图模式验收地理关系：示意模式检查大致方位、海陆关系、行程顺序，不新增经纬度、距离矩阵或海岸公里数检查；地理比例模式检查点位来源、统一映射及底图匹配，不把路线连线说成真实道路。地图模式留在内部制作记录中；展示页面不加比例或道路准确性说明。左下角最底部只显示整个行程日期，检查初始、滚动、展开、保存重开后不变。

## 浏览器检查

实际打开输出副本，使用宿主提供的浏览器能力，或已有的浏览器测试环境；不能调用时写明未验证，不把静态检查改称浏览器通过。

1. 桌面半屏检查首屏、途经章节和结尾；建议 1440×900，另检查一个较窄桌面宽度。首屏为概览，滚动后才放大；前进、反向滚动时路线、载具、标签与章节对应。
2. 展开全图、关闭、调整窗口大小后没有露底、重复节点或标签缩小。
3. 有素材时检查图片全部加载、透明边缘和视觉一致性；文字不被遮挡。不能只用浏览器大图模式评估半屏图标。检查图标主体清晰、标签对应易读、载具明显小于景物且不遮挡；具体参照地图美术流程。
4. 替换封面照片，确认封面替换入口和正文照片操作都可用。检查编辑提示明确区分“完成”和“保存”。编辑一段测试文字、添加便签，复制一张测试图到 `photos/` 并添加、排序。不要修改用户原图；测试文件可在隔离副本中使用抽象占位图。
5. 保存下载的新 `index.html`，放回测试副本。关闭旧页面，用没有 localStorage 草稿的新上下文打开，确认文字和图片保留、地图和路线完整。再编辑保存重开一次，检查标签、节点、工具栏没有成倍增加。
6. 打开浏览器控制台，处理阻断运行的错误。将测出的结果与没有条件验证的内容分开报告。

## 交付

交付目录包含 `index.html`、`photos/`、`assets/`、`map-art/`（有插画时）、`fonts/`、`vendor/`、`licenses/` 以及简短打开保存说明；按实际用途保留用户的项目制作记录。不把整个 skill、测试结果、浏览器缓存、临时截图或别人的素材塞进用户成品。

本地制作默认交付完整文件夹和 index.html 路径，不生成额外 ZIP。仅云端或聊天环境需要下载完整项目，或用户明确要求压缩包、分享、打包备份时生成 ZIP；不能仅因支持附件就打包。后续修改也不自动重打包。Skill 的安装分发包与用户手账成品是两种交付物，不要混淆。

完成交付的聊天回复中主动提一句：“如果需要分享或打包，跟我说就可以。”无需让用户立即选择，也不要先行生成 ZIP。

用户需要知道的只有：

- 电脑双击项目文件夹里的 `index.html` 打开；如果领取的是 ZIP，先完整解压。
- 照片先复制到 `photos/`，再点编辑添加；文字和便签可直接修改。
- 点保存后，把下载的新 `index.html` 放回同一文件夹替换旧文件；替换前备份整个文件夹。
- 分享 ZIP 后，朋友在电脑上完整解压，再打开 index.html；不能只发 HTML。

如浏览器限制导致双击不能用，依据实际错误处理；必要时给可运行的简单本地服务启动方法，不一开始就把命令行作为用户门槛。完成状态应明确：地图已精修 / 地图插画待补 / 用户照片可后补，以及实际做过哪些检查。

## 分享与备份

用户要求分享时，只问一个问题：“要把原始照片也一起放进分享包吗？”给出“不包含（推荐，体积较小） / 包含原图”两个选择；可在同一句补充原图会增加体积，并可能保留拍摄信息。用户已明确选择时不重复问；未回答时不擅自纳入原图。没有原图则说明只打包现有运行素材，无需空问。

制作独立分享副本：包含 index.html、被引用的网页照片、背景、插画、字体、动画库、许可和简短打开说明。根据实际引用核对资源，不机械压缩整个工作目录。默认排除原图备份、制作日志、坐标明细、样稿、测试截图及缓存；用户选包含原图时，将其额外放入 originals/，不覆盖网页照片、不改变原图。压缩文件包含一个完整项目目录，解压到新目录后验证资源加载和滚动可用。完整备份按用户备份需求处理，不混称分享包。

## 容易漏掉的验收

- 用确认方案核对地图显示点、正文章节数，不擅自恢复所有景点。主要点均有需要的插画，不能以旗子版本报完成。
- 占位图文件总数最多一张，照片选择器不混入占位图或地图图标。没有实拍时有空状态；添加一张照片后再次打开窗口、保存重开后仍能找到；中文、空格、# 等文件名可正常加载。
- 对照原始行程核对地点名称与基本区域，不把模型推断记录当作原文。检查星期/日期一致、正文没有擅自增加第一人称感受或未经核实的攻略。
- 照片已接入时，删除“照片都未添加/来自另一趟旅行”等过期描述；占位图与实拍描述明确区分。
- 聊天、下一步.md、打开与保存.md 和页面制作状态一致；插画完成后不能仍显示制作中。保留背景选项的处理结果，明确右侧哪些实拍可后补，封面操作等说明与实际能力一致。
