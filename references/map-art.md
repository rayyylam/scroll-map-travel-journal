# 地图插画制作

目标是“能读懂的地图 + 统一的地点插画”，不让生图模型承担精确路线、可编辑文字和交互。

地图模式只决定点位是否按地理比例安排，不降低插画精修标准。示意模式不需要等待完整经纬度表、距离计算或精描底图；地点身份与大致关系清楚后，就可以开始代表性插画样稿。生图提示词无需填入经纬度或离海岸多少公里。

## 先确定一组规则

查看 `assets/style-reference.jpg` 或用户自己的视觉参考。默认可借鉴米白、青绿、湖蓝、深墨色轮廓、少量珊瑚橙，轻微纸张/丝网印刷颗粒。陆地旅行按景物改变配色比例，不强制满屏海水。

从用户真实停靠点选代表物：城市地标、桥梁、森林、建筑、山体、动物等。先列出已确认需要插画的地图点，再做两个不同类型的样稿，在半屏地图中检查轮廓、细节和大小是否合适。风格已确定后，用同一参考图及获认可样稿约束后续生成；不要仅靠重复风格形容词。

## 给实际生图工具的约束

- 每个文件一个独立景物或紧凑的景物组合，真实透明背景，PNG 或带 alpha 的 WebP。不能把棋盘格画进图片冒充透明。
- 按可用工具支持的尺寸生成，通常最长边 1024 左右已足够；按网页实际显示尺寸检查清晰度，不迷信固定分辨率。主体完整，有少量透明留边，无大块空白。
- 同组图片保持相近视角、描边粗细、颗粒和视觉重量；避免一张照片质感、一张扁平矢量、一张 3D。
- 无地名、日期、字母、编号、路线、箭头、框线、水印；这些由网页绘制。景物不包含无关交通工具。
- 输出保存到用户项目的 `map-art/<place-id>.png` 等稳定本地路径，并建立地点 ID 与素材的对应记录。
- 优先开启生图工具实际支持的透明输出参数，检查结果；已透明的图片不重复抠图。需要去背景时，优先复用环境已有的图片编辑或抠图能力。必须额外安装工具或下载抠图模型时，先简短说明原因、预计耗时（未知则如实说明），让用户选择继续或交回处理好的透明图片；不默认搭建 Pillow/rembg 等整套环境。一次工具的失败不意味着所有工具都不能透明输出。没有处理能力时明确缺口，不伪称已完成。

## 单张提示词骨架

按当前目的地填写具体内容；不要将占位符原样交给工具：

> 参考附图的视觉语言，为旅行地图制作一个独立的【地点/景物】插画。主体识别特征是【2—3 个有依据的特征】。复古手绘旅行海报风，柔和色块、轻微丝网印刷颗粒、深墨色略不规则轮廓。沿用参考样稿的视角、配色、描边和细节密度。主体紧凑、轮廓清楚，缩小到地图上仍能辨认。透明背景，主体完整不裁切，少量透明留边。不画文字、日期、数字、路线、箭头、边框或水印。只参考附图风格，不复制附图中的行程和地点。

透明背景除了文字提示，还要设置工具支持的透明输出参数。有工具时直接生图，不只给用户返回提示词。使用图片工具的专用调用规范，不能以手写 SVG 替代这一阶段。

## 没有生图能力时

明确告诉用户“当前环境可以做网页，不能生成地点插画”。给出短表：地点、建议景物、输出文件名、每张完整提示词，并提供可下载/可查看的参考图。用户只需在自己可用的生图工具中生成并交回图片，不需要研究图层坐标。此时交付状态是“可用结构初版，地图插画待接入”；如果用户明确接受简洁矢量风，则按其选择完成并说明实际使用的方式。

不硬编码某家图像模型，不要求安装第二个 skill，不假设存在 API 凭证。Skill 约束的是流程和交付标准，跨模型视觉质量要由样稿和实际预览判断。

## 接入后的美术检查

- 底图与景物融合，背景没有不透明方块、白边或假透明网格。
- 在电脑半屏与全图中检查实际景物主体，而非 PNG 画布尺寸：先处理过多透明留白，再按主体统一视觉重量。图标应清楚可辨，不能小到只看得见标签；标签不压景物，引线不因避让过长或对应混乱。
- 载具是小型进度标记，屏幕上的大小应明显小于主要景物；检查出发、到达及中途，不让车/船/飞机遮住地标。先调整图标和载具尺寸、偏移及图层，不用重生成整套图片。
- 插画随镜头缩放，地名保持屏幕可读字号；细小过路点可只用节点。
- 纹理低对比，不抢路线和标签；不通过增加大量小岛、装饰或颗粒来弥补布局问题。
- 图片真实写入项目并被页面引用。核对全图、放大、反向滚动、保存重开。

## 可选背景美化

地点插画完成后、照片编辑引导前，询问保留当前背景或美化背景；一次选择即可。已选择跳过则直接继续，已经有明确背景要求则按要求完成。

优先保留海岸线、海陆分区、点位、路线和镜头，只调整纸张、海面和地形装饰，使配色、颗粒和细节密度与地点插画协调。可用现有样式；需要生图时生成无文字、无路线、无地标和精确地形要求的低对比纹理，放在 assets/，用 SVG 区域裁剪/图案填充限制海陆范围。纹理无需透明背景，不引入抠图。

背景随地图使用同一坐标与缩放，覆盖全部镜头范围，检查边缘、接缝、标签可读性和保存重开。先在实际地图里展示一版；保留可恢复的旧背景。不要默认生整张地图，再为匹配路线重新校准地点。用户跳过或暂缓时保留清爽背景并继续，不能把此可选项变成完成门槛。

## 每次阶段交付必须有下一步

建立一个简短插画清单（地点｜代表物｜文件名｜待生成/待确认/已接入），保存在用户项目的 materials/journey.md。用户不需要填写技术字段。

- 有生图能力：初版路线确认后主动继续制作两个样稿。需要样稿确认时，在聊天中展示地图里的实际效果并说“确认这两张的风格后，我会继续完成清单中的其余地点”，不能只交网页后停住。
- 没有生图能力：聊天中明确说明缺少生图能力，给已填写的逐张提示词与参考图文件链接、输出命名；说明用户把生成图片交回来后由 AI 完成接入。不能只说“你可以自己生图”或要求用户另找模板。
- 工具失败：说明哪几张未完成、哪些已经保留、可用的后续处理方式。不能用手写 SVG 静默替代。
- 所有已确认需要插画的点完成接入后，才称地图精修完成。右侧尚无实拍不影响这个判断，右侧通用占位图也不能算作地点插画。

同步更新项目的 下一步.md，让用户下次打开文件夹能看懂进度。地图步骤不藏在代码注释、待办列表或其他技术文档里。
